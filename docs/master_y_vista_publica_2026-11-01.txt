registro, correo simulado, configuración básica y vista de empresa lista.
No crea cuentas o bases reales, no solicita contraseñas y no envía correos.

segunda implementación manual del diseño. La capa de API simulada reemplaza
la comunicación con servicios reales. Los scripts se encapsulan para no
alterar variables globales de Odoo/jQuery. Se detectó y corrigió ese conflicto
durante la revisión de la nueva página; no se reemplazaron recursos globales.

MÁSTER PARA CLIENTES
Un solo repositorio y una base de código versionada: main en uno360x-saas.
Cada empresa conserva su propia base, archivos y credenciales. No se usa
la base operativa de OUTSOLUTECH como plantilla o base compartida de clientes.
Una versión se identifica por commit y hash del artefacto. Cada cliente deberá
registrar qué versión tiene. Las actualizaciones solo afectan módulos que
le correspondan y no habilitan módulos pagados por el hecho de actualizar.
Orden de distribución: pruebas -> respaldo -> migración por cliente ->
verificación -> siguiente grupo. Ante fallo, detener distribución y recuperar
con el procedimiento validado. OUTSOLUTECH conserva sus privilegios propios.
product/release_policy.json recoge esta política. El motor comercial de
actualización por lotes todavía está pendiente; no hay despliegue automático
a todos los clientes por cada push a GitHub.
